# Web project guide

The UI is a French-language Next.js 16 app. Code and comments are English.

## Layout

```text
src/app/page.tsx                 dashboard page (home)
src/app/_components/             dashboard widgets, server card, create form, server detail
src/app/servers/new/page.tsx     create server page
src/app/servers/view/page.tsx    static server detail (name from ?name=<name>)
src/app/servers/[name]/          detail panels/settings (no route; imported by the view)
src/app/api/[...path]/route.ts   server-side API proxy (injects the bearer token)
src/proxy.ts                     Basic auth, same-origin check, /servers/<name> redirect
src/components/app-shell.tsx     sidebar/topbar shell, composed by each page
src/components/theme-toggle.tsx  light/dark toggle
src/lib/api.ts                   the only browser API client
src/lib/format.ts                French dates and relative times
src/lib/server-status.ts         French status labels and tones
src/lib/settings/                settings catalog, sections and controls
src/components/ui/               shared UI primitives
```

## Commands

```sh
pnpm --filter @factorio/web test
pnpm --filter @factorio/web lint
pnpm --filter @factorio/web exec tsc --noEmit
pnpm --filter @factorio/web build
```

Tests are Vitest tests for pure helpers in `src/lib/*.test.ts`. Add a test when
you add or change address formatting, operation labels, resource validation,
status labels, date formatting or another pure function.

## Rules and pitfalls

- Never call the API from the browser with the bearer token. Use
  `src/lib/api.ts`; the proxy injects the token server-side.
- Keep UI labels, help text and toasts in French.
- The root layout must stay minimal (`ThemeProvider`, `Toaster`). Each page
  composes `AppShell` itself. Do not move the shell or an app footer into the
  root layout: a client wrapper/footer around all pages broke hydration under
  Cache Components (the footer was removed for this reason).
- The home dashboard is a client page. It polls every 30 seconds and shows its
  own skeleton; do not assume a server-rendered server list.
- The server detail is the static `/servers/view?name=<name>` page. `proxy.ts`
  redirects `/servers/<name>` to it. Keep the detail name in a child effect and
  do not reintroduce `useParams` or a server `params` page without verifying a
  production build: that route stayed in a loading shell under
  Cache Components.
- Server detail pages poll operations every 5 seconds and disable actions while
  an operation is active. Do not bypass this lock in new buttons.
- Settings updates use `metadata.generation`. On 409, keep local edits and show
  the reload banner; do not silently overwrite.
- Backups and imports can run only when the server is running; the saves
  sidecar serves the list and usage.
- Use the shared `DeleteServerConfirmation` component for destructive server
  deletion; keep the data checkbox checked by default.
- The Next.js rules block above is regenerated by `next dev`. Do not remove it;
  commit it if it changes.
- The sidebar shows `NEXT_PUBLIC_APP_VERSION`, baked at build time. Local builds
  fall back to `dev`; release images receive the Git tag.
